Cardinal A3

Privacy and data use

Cardinal is a restricted classroom prototype. Its connected mailbox, calendar and project content must contain synthetic test data.

Information the application accesses

With the test account owner’s Google authorization, Cardinal can read test Gmail messages and their metadata, send a reviewed test message, and read the dedicated app-created assignment calendar. Setup can create synthetic events in that calendar; the agent’s runtime calendar tool is read-only.

The application also processes chat requests, synthetic preferences and deadlines, email drafts, approval records, and activity or routing metadata needed to operate and demonstrate the project.

Why it uses this information

Data supports inbox summaries, schedule planning, email drafts, briefings, alerts, recaps and persisted preferences. The application restricts email recipients and requires authenticated human approval of each exact message before sending. A model response cannot provide that approval.

Model and service processing

Relevant context may be processed by the configured OpenAI cloud model or by Gemma through Ollama on the operator’s laptop. Requests marked private or confidential, and later turns in that private conversation, stay on the local model path. If the local model is unavailable, those requests are held instead of sent to cloud. Non-private tasks may use cloud fallback.

Google provides the mailbox and calendar APIs. Google Cloud hosts the agent, private state and credentials. Tailscale carries private access and inference connections. Telegram receives approved assistant notifications addressed to the configured owner. Weather and search use their configured public-source services.

Storage and access

Drafts, preferences, deadlines, approval records and activity logs are stored in the assignment project, with private cloud backups. Credentials are stored separately using private local staging and Google Secret Manager. Routing logs retain model, reason and outcome metadata, without message text; framework conversation history and approved notifications can contain synthetic content.

The operator and authorized graders receive access to inspect the agent and dedicated test accounts for assessment. Trusted infrastructure administrators and configured processors may also process data to provide their services. The public information site does not display test records, credentials or grader invitations.

Retention, consent and deletion

Project records are retained for assignment grading and regrades. Records are not automatically purged; the operator must delete stored records and resources when they are no longer needed. The account owner can revoke the application’s access through Google Account settings. Revocation stops future authorized API access but does not automatically erase previously stored project records. Contact the operator to request their deletion.

Limited use

Cardinal does not sell Google user data, use it for advertising, or run general-purpose model-training jobs. Google API data is used for the assistant features described here and is subject to the Google API Services User Data Policy, including its Limited Use requirements.
